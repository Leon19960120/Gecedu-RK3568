## 4. 报错分类

### 4.1 功能受影响（需修）

#### (1) MIPI DSI 屏不显示 / framebuffer 打不开  ⭐最高优先级

```text
panel-simple-dsi fe060000.dsi.0: not found firmware desc data, using defaults
panel-simple-dsi fe060000.dsi.0: Expected bpc in {6,8} but got: 0
Starting launcher: Error: cannot open framebuffer device: No such file or directory
```

**根因分析（对照 6.1 内核代码）：**

面板节点（`rk3568-evb-gec.dtsi:409` `dsi0_panel`）写法为：
```dts
dsi0_panel: panel@0 {
    status = "okay";
    compatible = "simple-panel-dsi";   // Rockchip BSP 私有 compatible
    reg = <0>;
    backlight = <&backlight>;
    reset-gpios = <&gpio3 RK_PA7 GPIO_ACTIVE_LOW>;
    ...
    dsi,format = <MIPI_DSI_FMT_RGB888>;
    dsi,lanes  = <4>;
    panel-init-sequence = [ ... ];     // Rockchip 私有属性
};
```

6.1 内核 `drivers/gpu/drm/panel/panel-simple.c` 里 `"simple-panel-dsi"` 仍被支持（`panel-simple.c:5167`），走 `panel_simple_dsi_probe` → `panel_simple_dsi_of_get_desc_data` 动态建 `desc`。

关键在 `panel_simple_dsi_of_get_desc_data`（约 `panel-simple.c:4857`）：
```c
if (desc->num_modes || desc->num_timings) {        // ← 守卫
    of_property_read_u32(np, "bpc", &desc->bpc);   // 只有有 timing 才读 bpc
    ...
}
```

GEC 面板节点**没有 `panel-timing` / `display-timings` 子节点** → `desc->num_modes == 0` → `of_property_read_u32(np, "bpc", ...)` **不执行** → `desc->bpc` 保持默认 0。

之后 probe 的 `DRM_MODE_CONNECTOR_DSI` 分支（`panel-simple.c:994`）：
```c
if (desc->bpc != 6 && desc->bpc != 8)
    dev_warn(dev, "Expected bpc in {6,8} but got: %u\n", desc->bpc);
```
→ 报 `bpc=0`，且 `connector->display_info.bpc` 不被设置（第 504 行 `if (panel->desc->bpc)` 跳过），framebuffer 创建失败。

> **对比 5.10**：5.10 同类路径没有 `if (num_modes)` 守卫，或 Rockchip 分支直接给 `simple-panel-dsi` 默认 `bpc=8`，所以 5.10 不报错、屏正常。

**修复方向（待板上验证，未改 DTS）：**
- 方案 A：给面板节点补 `panel-timing`（或 `display-timings`）子节点，让代码走到读 `bpc` 的分支，同时在节点加 `bpc = <8>`（RGB888 → 8 bpc）。
- 方案 B：若 `panel-init-sequence` 已内含时序，需在 6.1 找到对应的 Rockchip 补丁逻辑（6.1 上游 `simple-panel-dsi` 是否仍解析 `panel-init-sequence` 并自动推断 timing，需进一步核对 `panel_simple_dsi_of_get_desc_data` 全函数）。
- 注意：`bpc = <8>` 单独加**不够**——没有 timing 时它不会被读取（被 `if (num_modes)` 挡住）。

#### (2) 耳机检测丢失

```text
rockchip_headset rk-headset: Can not read property hook_gpio
rockchip_headset rk-headset: have not set adc chan
```
因覆盖了 6.1 原版 `multicodecs-card`+`hp-det-gpio`+`hp_det` pinctrl，换成 5.10 的 `simple-audio-card`。音频本身可用（`#1: rockchip,rk809-codec`），耳机插拔检测不可用。修复需恢复 6.1 的耳机检测节点（或把 5.10 的 `headset` 检测方案迁过来）。

#### (3) USB gadget 复合功能创建失败

```text
mkdir: cannot create directory '.../functions/uac1.gs0': No such file or directory
（uac2.gs0 / mtp.gs0 / rndis.gs0 / hid.usb0 同样）
```
内核未编入对应 USB 功能（或模块未加载）。adb/mtp/rndis 等不可用。不需要可忽略。

### 4.2 无害噪声（不影响启动，常见）

### 6.6 本次结论

1. DTS 覆盖成功：V11 板型名、WiFi 唤醒脚生效，板子正确识别为 GEC V11。
2. 屏不亮是唯一"用户可见"硬伤，根因确认为 `panel-simple-dsi` 的 `bpc=0`（§4.1(1) 代码级定位）。显示 pipeline 绑定正常，只差 `bpc` 属性。
3. 其余报错均为已知无害项或可选功能（USB gadget / 耳机检测）。
