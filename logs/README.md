平台：Rockchip RK3568 评估板，LPDDR4 2GB

本批日志抓取时间：2026-03-05 至 2026-03-11

## 命名规则

2026 年 3 月的原始串口日志统一采用：

```text
YYYY-MM-DD_HHMM_板卡状态_操作或记录范围_可直接确认的结果.log
```

- 日期时间主要取原文件最后修改时间；MobaXterm 文件优先采用文件名内的抓取时间。
- `BadHash_4A897379`、`BadHash_CA79EDC3` 是实际计算出的 SHA-256 值前 8 位，用于区分两类损坏镜像。
- `进入root-shell` 只表示日志已到达命令行，不代表全部外设测试通过。
- `多轮启动`、`混合抓取` 表示同一文件串接了多个启动周期，不能把整份文件当成单次启动。
- 文件名记录可验证的现象，不把 `mtd_boot`、MMC 探测告警或 DDR 训练偏差直接写成未经证明的根因。

完整旧名与新名对照见 [`2026-03_日志重命名对照.md`](2026-03_日志重命名对照.md)。

## 与 CC 镜像调查直接相关的结论

1. `4A897379...` 是尾部被 `0xCC` 替换的 32 MiB `boot.img` 所计算出的内核哈希；它与 FIT 中期望的哈希不一致，因此 U-Boot 拒绝启动内核。
2. `CA79EDC3...` 是另一类 Bad Hash，不能仅凭现有文件把它与 `4A897379...` 视为同一份坏镜像。
3. `mtd_boot not defined` 出现在 U-Boot 启动失败后的回退路径中；它能解释该行报错，但不能解释 boot 内核数据为什么变成 `0xCC`，也不是 FIT Bad Hash 的根因。
4. 正常板日志同样可能出现对另一路 MMC/SD 的 `Card did not respond to voltage select`，所以该行不能单独证明 eMMC 故障。
5. 多份旧日志串接了成功和失败启动周期。判断因果时必须按每个 `DDR Version`/U-Boot 启动头分段，不能只根据整份文件是否含某个关键词下结论。
